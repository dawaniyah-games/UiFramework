The screen and popup framework for Unity game UI

Build every screen as its own Addressable scene. A state stack decides what is on screen, shared elements like your nav bar stay put, every transition is animated with no flash, and a Unity editor window generates the scripts, scenes and config for you.

Why teams use it

One scene per screen

Each UI element is an Addressable scene. Artists and designers work in their own scene without merge fights, and memory follows exactly what is on screen.

A real state stack

Replace the whole UI, or push popups and overlays on top. Close them with one call. No hand-rolled screen managers, no forgotten canvases.

Shared elements stay put

A nav bar or currency header used by several screens stays loaded and on screen while the screens change underneath it. It never reloads and never re-animates.

Animated by default

Ten calm, tuned presets: fade, zoom, four slides, pops and shake. Pick one per element in the editor, or override it for a single call from code.

No flash, no empty frame

The new screen animates in while the old one animates out. Elements are prepared in their start pose before their first frame, so nothing pops.

Editor tooling

The UI Setup Manager creates element scripts and scenes, builds states, validates every scene, fixes structure in one click and generates the runtime config.

How it works, in one picture

You define states (a screen, a popup) as lists of element scenes. At runtime, UiManager loads the scenes a state needs, hands every element its data, plays the transitions and unloads what nothing uses any more.

Get started

From install to your first screen

Install the package, open the UI Setup Manager and show a screen from code. The Tutorial walks through every step with screenshots and videos.

Requirements

Unity2021.3 or newer (the showcase project uses Unity 6)
Addressables1.21.0 or newer, installed automatically as a dependency
UIUGUI (com.unity.ugui). Any content works inside your scenes: Text, TextMeshPro, images, your own components
PlatformsEverything Unity and Addressables support. All animation runs on unscaled time

1. Install the package

In Unity, open Window → Package Manager → + → Add package from git URL… and paste:

Package URL
https://github.com/dawaniyah-games/UiFramework.git?path=Packages/com.dawaniyahgames.uiframework

To pin a version, append #vX.Y.Z (see Releases), or add it to Packages/manifest.json:

Packages/manifest.json
{
  "dependencies": {
    "com.dawaniyahgames.uiframework": "https://github.com/dawaniyah-games/UiFramework.git?path=Packages/com.dawaniyahgames.uiframework#v1.2.0"
  }
}

2. Set up the project

  1. Open UiFramework → UI Setup Manager.
  2. In the General tab press Create Config. Set your script and scene folders and your game's namespaces on the created UiEditorConfig.
  3. Check the Global Canvas Settings in the same tab: every new element scene starts with them.

3. Make your first screen

  1. Elements tab → ➕ New Element → name it MainMenuUiElement → Create. You get the script and a scene laid out as MainMenuUiElementRoot → Canvas → Root.
  2. Build your UI under Root and pick a show and hide animation in the element's Animations section.
  3. States tab → type MainMenuUiState next to New state → ➕. Add the MainMenuUiElement scene to it.
  4. General tab → Build Runtime UiConfig. Run it again after every state or scene change.

4. Show it from code

UiManager creates itself; don't add it to a scene. It loads the generated config from Addressables.

GameBootstrap.cs
using System;
using UiFramework.Runtime.Manager;
using UnityEngine;

public class GameBootstrap : MonoBehaviour
{
    // async void is fine for Unity messages, as long as exceptions are caught and logged.
    private async void Start()
    {
        try
        {
            if (!UiManager.IsInitialized)
            {
                await UiManager.InitializeAsync();
            }

            await UiManager.ShowState<MainMenuUiState>();
        }
        catch (Exception exception)
        {
            Debug.LogError("[GameBootstrap] UI failed to start: " + exception);
        }
    }
}
Press Play

With the Addressables play mode set to Use Asset Database (Window → Asset Management → Addressables → Groups → Play Mode Script), the screen appears right away. For a player build, build Addressables content first.

5. Give the screen its data

Whatever you pass to ShowState reaches every element of the state in Populate. Keep Populate idempotent: it runs again when another state reuses the scene.

MainMenuUiElement.cs
using UiFramework.Core;
using UnityEngine;
using UnityEngine.UI;

public class MainMenuParams : UiPopulationParams
{
    public string PlayerName { get; set; }
}

public class MainMenuUiElement : UiElement
{
    [SerializeField] private Text welcomeLabel;

    public override void Populate(object context = null)
    {
        base.Populate(context);

        MainMenuParams data = context as MainMenuParams;
        if (data == null)
        {
            return;
        }

        welcomeLabel.text = "Welcome back, " + data.PlayerName;
    }
}
Showing it with data
MainMenuParams data = new MainMenuParams();
data.PlayerName = "Alex";

await UiManager.ShowState<MainMenuUiState>(data);

Tutorial

Build a screen with the UI Setup Manager

Ten steps from an empty project to a working screen with a popup. Every step has a short video. Open the editor with UiFramework → UI Setup Manager.

Video series

    Steps

    1. Config 2. New element 3. Build the screen 4. Animations 5. Validate 6. Canvas & Addressables 7. States 8. Build config 9. Show it 10. Add a popup

    1. Create the config and check the canvas defaults

      Open the General tab and press Create Config. It finds or creates a UiEditorConfig asset that tells the tools where your scripts and scenes live and which namespaces to generate into.

      • Set ElementNamespace and StateNamespace to your game's namespaces.
      • In Global Canvas Settings, choose the render mode and the Canvas Scaler values (default: Scale With Screen Size, 1080 × 1920, Expand). Every new element scene starts with them.
      Defaults, not enforcement

      Changing the global settings never edits existing scenes. Each element can still differ, or adopt the defaults with Use Default Settings….

    2. Create a UI element

      Open the Elements tab and press ➕ New Element. The form opens in the right panel:

      NameThe class and scene name, e.g. StoreUiElement
      From Existing SceneOptional: convert a scene you already have. Its objects move under the new root, and you are offered a structure fix
      Include Parameters ClassAlso generates StoreUiElementParams for the data you pass in
      Include Reference ClassAlso generates a StoreUiElementReference helper

      Press Create. You get the script and a scene built to the scene contract. After Unity compiles, the script is attached to StoreUiElementRoot automatically. An existing script with the same name is never overwritten.

    3. Build the screen under Root

      Open the scene (double-click it in the list). Every element scene has the same shape. Put all of your content under Root: that object is what animates.

      • Lay things out with normal anchors; the Canvas Scaler handles screen sizes.
      • Nested canvases are fine under Root (for example a layer with a high sorting order).
      • Nothing may sit next to Root under the Canvas, or it won't animate.
      • Popups usually put a full-screen dimmed backdrop as the first child of Root.
      StoreUiElementRoot UiElement script, the only root object └─ Canvas Canvas + CanvasScaler + GraphicRaycaster └─ Root stretched, the animation target ├─ Header ├─ ItemsGrid └─ … all your content

    4. Pick the show and hide animations

      Select the element in the list. In its Animations section, choose a Show and a Hide preset. Each choice shows one line describing what it looks like, and the change is written straight into the scene.

      See every preset moving on the Animations tab. Code can still override them for a single call with UiTransition.

    5. Validate and fix scene structure

      Every scene in the list has a status: ✓ OK, ⚠ fixable, ✖ needs work by hand.

      • Validate All logs one line per scene with its issues.
      • Fix Structure… (one element) or Fix All Structure… shows exactly what will change, with a Now / After preview of the hierarchy, before it touches anything.
      • Fixes only create and reparent objects, with Undo. They never delete anything; what needs manual work is listed under What to fix by hand….
      • Only show elements with issues filters the list.

    6. Canvas, sorting and Addressables per element

      The Canvas section edits this scene's Render Mode, Sorting Order, UI Scale Mode, Reference Resolution, Screen Match Mode and Reference PPU in place. Use sorting order to stack layers, for example screens 0, bars 10, popups 100.

      The Addressables section shows whether the scene is Addressable, its group and labels. Build Runtime UiConfig registers every scene a state uses for you.

    7. Create a state and add its scenes

      Open the States tab. Type the state name next to New state (for example StoreUiState) and press ➕. It generates the state class: a type marker for ShowState<StoreUiState>(). Its name must equal the state key.

      Select the state and use Add element scene: start typing and pick from the suggestions. Add the screen and every shared element it shows, for example StoreUiElement, TopBarUiElement and NavBarUiElement.

      Shared elements

      List your nav bar in every tab state. While you switch tabs it stays loaded and on screen, and only the screens animate.

    8. Build the runtime config

      Back in General, press Build Runtime UiConfig. It turns your state definitions into the runtime UiConfig, makes every element scene Addressable (group UiElements) and registers the config under the address UiConfig.

      Run it after every change

      New state, renamed scene, added element: build again. The config is generated, so never edit it by hand. For player builds, also build Addressables content.

    9. Show it from code and press Play

      Initialize once at startup, then show states from anywhere: buttons, game events, your flow controller.

      From a button
      private async void OnStoreClicked()
{
    try
    {
        await UiManager.ShowState<StoreUiState>();
    }
    catch (Exception exception)
    {
        Debug.LogError("[HomeUiElement] Could not open the store: " + exception);
    }
}

    10. Add a popup

      A popup is a state shown with additive: true. It goes on top; the screen below stays loaded and visible. HideUI pops it again.

      1. Create ConfirmPurchaseUiElement, give it a dimmed backdrop and a panel, and set its Canvas Sorting Order above your screens.
      2. Create ConfirmPurchaseUiState with just that scene, and build the runtime config.
      3. Open it with data, close it from its buttons:
      Popup
      ConfirmPurchaseParams purchase = new ConfirmPurchaseParams();
purchase.ProductId = "neon_blade";

await UiManager.ShowState<ConfirmPurchaseUiState>(purchase, additive: true);

// In the popup's Cancel / Buy handler:

    Checklist when something doesn't show

    • The state class name equals the state key exactly.
    • Build Runtime UiConfig ran after your last change.
    • The Addressables play mode script is Use Asset Database, or content is built.
    • The element's scene shows ✓ in the Elements tab.
    • There is one EventSystem and, for Screen Space – Camera canvases, a camera assigned at runtime.
    • The Console has no [UiManager] errors.
    Concepts

    How the framework thinks

    Five ideas explain everything: element scenes, states, the stack, context and shared elements.

    Vocabulary

    TermMeaning
    Element sceneA Unity scene with one root object <Name>Root holding a UiElement. The unit of loading.
    UiElementA MonoBehaviour that receives data in Populate(object context) and owns its show / hide animation presets.
    StateA named set of element scenes, identified by a state key, e.g. StoreUiState.
    ContextThe object passed to ShowState, forwarded unchanged to every element of the state. Usually a UiPopulationParams subclass.
    Shared elementA scene used by consecutive states. It stays loaded, is re-populated, and is not animated.

    An element's lifecycle

    The state stack

    Non-additive (the default) replaces the whole stack: the new state animates in while every state on the stack animates out, then the old states are released.

    Additive pushes on top, for popups and overlays. The states below stay loaded and visible.

    HideUI() pops the top state, plays its hide animations and releases its scenes.

    ResetUIAsync() hides and unloads everything.

    Shared elements and reference counting

    Scenes are identified by their Addressables GUID and counted per state on the stack. The new state's scenes are counted before the old ones are released, so a scene used by both never unloads and reloads in between. A scene unloads only when its count reaches zero.

    State classes are type markers

    ShowState<StoreUiState>() finds the state whose key equals the class name. The runtime builds the state from the config, so code inside a UiState subclass never runs: keep behaviour in your elements. For keys without a class, use ShowStateByKey("StoreUiState").

    The element scene contract

    Animation targets the one object under the Canvas, so every element scene has the same shape. The Elements tab checks it and fixes it in one click.

    <Name>Root plain Transform with the UiElement subclass; the ONLY root object in the scene └─ Canvas child 0: root Canvas + CanvasScaler + GraphicRaycaster └─ Root the ONLY Canvas child: stretched RectTransform, the animation target └─ … all content (nested canvases are fine here)

    Good to know

    One call at a time

    Overlapping ShowState / HideUI calls are not queued for you. Await each call, or route navigation through one place that queues them (the showcase's ShowcaseNavigator does).

    HideUI and shared elements

    HideUI doesn't skip elements shared with the state underneath, so keep popups to their own scenes.

    Initialization

    IsInitialized is true as soon as the manager exists, before the config has loaded. Await InitializeAsync() before showing states.

    No data binding

    The framework hands each element its context. Updating what is already on screen (a coin counter) is your code, for example events on your data.

    Animations

    Calm, tuned motion out of the box

    Every element has a show and a hide preset, chosen in the Elements tab. Entrances ease out, exits are shorter and ease in, and every show and hide fades, so nothing pops in or out.

    The ten presets

    Each card loops: show, hold, hide.

    What makes them feel good

    Base pose

    Each object's resting position, scale and alpha are recorded once. Every preset starts from it and returns to it, so repeated or interrupted animations never drift.

    No skipped frames

    A long frame, like the one where a scene loads, slows an animation slightly instead of jumping past half of it.

    One animation per channel

    A new animation stops older ones driving the same thing (position, scale, alpha). A button pop doesn't stop a slide; a new show stops a running hide.

    No flash

    Right after its scene loads, an element is put in its show start pose, in the same frame as Populate.

    Overlapping transitions

    In a screen switch, the old state hides while the new one shows: no empty frame in between.

    Unscaled time

    UI keeps animating while the game is paused (Time.timeScale = 0).

    Override the animation for one call

    UiTransition replaces the presets for a single ShowState or HideUI call, without changing the elements' configuration. Shared elements stay still either way.

    UiTransition
    // Show the Store with a zoom this time, whatever its elements are configured to do.
await UiManager.ShowState<StoreUiState>(context, transition: UiTransition.ShowWith(TweenPresets.ScaleKey));

// Close the top state by sliding it out to the right.
await UiManager.HideUI(UiTransition.HideWith(TweenPresets.SlideRightKey));

// Both sides at once: the new screen enters moving left, the old screen leaves moving left.
await UiManager.ShowStateByKey("ProfileUiState", context, false,
    new UiTransition(TweenPresets.SlideLeftKey, TweenPresets.SlideLeftKey));

    Recipe: tabs that slide in the direction you tap

    From the showcase's ShowcaseNavigator
    // Moving to a tab on the right slides everything left (like swiping), and the other way round.
private static UiTransition GetTabTransition(ShowcaseTab from, ShowcaseTab to)
{
    if (from == to)
    {
        return UiTransition.Default;
    }

    string preset = (int)to > (int)from ? TweenPresets.SlideLeftKey : TweenPresets.SlideRightKey;
    return new UiTransition(preset, preset);
}

    Button feedback

    The pops and shake also work on any transform, without fading, as feedback:

    Feedback
    await TweenPresets.ClickPop(buyButton.transform);    // quick 1.08x pop
await TweenPresets.SettlePop(coinIcon.transform);    // gentle 1.04x pulse
await TweenPresets.ShakeLocal(buyButton.transform);  // "no": not enough coins

    Your own animation

    ShowAsync, HideAsync and PrepareForShow are virtual. Run extra motion next to the preset, or replace it completely. Tween.RunAsync gives you the same interruptible, frame-capped loop the presets use.

    Stagger the cards in after the screen's own preset
    public class StoreUiElement : UiElement
{
    [SerializeField] private RectTransform[] cards;

    public override void PrepareForShow()
    {
        base.PrepareForShow();
        for (int i = 0; i < cards.Length; i++)
        {
            cards[i].localScale = Vector3.zero;
        }
    }

    public override async Task ShowAsync(string presetKey = null)
    {
        Task screen = base.ShowAsync(presetKey);
        for (int i = 0; i < cards.Length; i++)
        {
            RectTransform card = cards[i];
            await Tween.RunAsync(card, 0.18f, TweenCurves.EaseOut, true, CancellationToken.None, null, eased =>
            {
                card.localScale = Vector3.one * eased;
            });
        }

        await screen;
    }
}

    Patterns worth copying

    One navigator

    ShowcaseNavigator is the only caller of ShowState / HideUI. It queues calls so they never overlap, keeps only the last tab tapped, and allows one popup at a time.

    Context everywhere

    Tab states get a TabUiParams; the shared NavBar reads the tab from the same object, so it is right however the tab was reached.

    Shared re-population

    The TopBar wires itself once and refreshes on every Populate. When the Store is already on screen, a second Populate switches its page in place.

    Popups that look right

    The popup's Fade preset fades the dimmed backdrop; only the panel moves, through a RevealOnShow, so the backdrop never slides.

    Inspector choreography

    RevealOnShow, StaggeredReveal, FillBar and CountUpText play when the element shows; LoopMotion, ShimmerSweep, ConfettiBurst and CoinFlyLayer add life.

    One camera, one EventSystem

    The bootstrapper keeps them in a DontDestroyOnLoad root, and UiCanvasCamera assigns the camera to every Screen Space – Camera canvas as its scene loads.

    FAQ & troubleshooting

    Answers before you ask

    Troubleshooting

    "No UI state key registered for MyUiState"

    The state class name must equal the state key exactly, and Build Runtime UiConfig must have run after you created the state.

    "Failed to locate UiConfig via Addressables"

    Run Build Runtime UiConfig, then make sure Addressables can find it: play mode script Use Asset Database in the editor, or build Addressables content for a player.

    Nothing appears on screen

    Check the element's status in the Elements tab (✓), that your content is under Root, that there is an EventSystem and, for Screen Space – Camera canvases, that a camera is assigned at runtime. Look for [UiManager] errors in the Console.

    My list doubles every time I come back to the screen

    Populate runs again when a state reuses the scene. Rebuild lists instead of appending, and guard one-time setup with a flag.

    Code in my UiState subclass never runs

    State classes are only type markers; the runtime builds states from the config. Put behaviour in elements.

    Two fast taps show the wrong screen

    Calls aren't queued for you. Await each call, or route navigation through one place that queues calls, like the showcase's ShowcaseNavigator.

    Questions

    Does it work with TextMeshPro, my own components, my art?

    Yes. The framework only cares about the scene's shape; anything UGUI can draw works inside Root.

    Screen Space Overlay or Camera?

    Both. Pick the default in Global Canvas Settings and per element in the Canvas section. With Camera, assign your UI camera at runtime as scenes load (the showcase's UiCanvasCamera shows how).

    Can I load UI scenes from a remote content server?

    Element scenes are ordinary Addressables, so any Addressables setup works, including remote groups.

    Is it heavy on mobile?

    Only what is on screen is loaded. Animations use a small allocation-light loop on unscaled time, and shared elements are never reloaded.

    Can I add my own animation presets?

    Override ShowAsync / HideAsync / PrepareForShow in an element for one-off motion, or contribute a preset to TweenPresets.

    What does it cost?

    Nothing. It's open source under the MIT license.
